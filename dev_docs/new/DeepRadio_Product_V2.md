## 1. DeepRadio 是什么

DeepRadio 在 GNU Radio Companion（GRC）上增加自然语言能力：用户用中文或英文描述通信任务，系统生成或修改可运行流图，给出指标、图和可核对的验证结论。

用户文本进入工作区后，系统识别任务类型、按任务走受控流程、用工具改工程，再把结果折回对话、状态栏和画布。确定性 Stage 与可选大模型 Subagent 共用同一套工程事实，产出流图和 Claim-Evidence。

产品形态：单会话、单活动任务、串行阶段。仿真、诊断、修改、观测、硬件配置和受控发射共用同一工作区。每次空口声明都需要独立的接收端 Evidence。

## 2. 用户能完成的七类任务

任务类型按最终产物、验收方式和安全边界划分。BPSK、QPSK、OFDM 是仿真任务里的参数。BLE 空口部署是硬件配置任务中的部署操作。

| 用户目标 | 系统任务 | 用户应看到的结果 |
|---|---|---|
| 做一条完整仿真链路并验证 | 端到端仿真 | `.grc`、EVM 等指标、星座/频谱图、当前版本的 Claims |
| 只做发射链路（仿真） | 构建发射机 | 发射机流图和结构校验 |
| 做接收机并测误码 | 构建接收机 | 接收机流图、BER、与发送参考对应的证据 |
| 解释当前工程问题，先别改图 | 诊断 | 原因、证据、最小修改建议；画布和版本不变 |
| 把已有工程改成另一种方案 | 修改工程 | 先停在确认；批准后出新版本并重验；拒绝则工程不变 |
| 只看频谱、星座或指标 | 观测 | 图和指标；工程不被修改 |
| 规划或配置 SDR / 有限发射 | 硬件配置 | 配置、预检、确认；未确认不得发射 |

复合请求按终态范围最大的任务处理。例如「构建 BPSK 并配置到 USRP」走硬件配置，并补齐建图前置。

### 2.1 端到端仿真

规格完整时直接建图并仿真。EVM 不满足时可自动重试一次；仍失败时停下来等用户。

```text
做一个 BPSK 过 AWGN 的基带链路，EVM 要小于 10%，并显示星座图和频谱。
```

### 2.2 构建发射机

```text
构建一个 QPSK 基带发射链路，只做仿真，不接真实硬件。
```

该约束下不应出现设备发现或发射确认。

### 2.3 构建接收机

缺少必要接收规格时应先问清楚，用户补充后延续同一任务。BER 必须来自发送参考和接收判决两个数据来源。

```text
构建一个自包含的 BPSK AWGN 接收机，包含定时恢复和判决，并测 BER。
```

### 2.4 诊断

「先不要修改」是只读：可以给建议，不能改图、不能新建快照、不能覆盖 `.grc`。

```text
诊断当前链路的 EVM，解释主要原因并给出最小修改建议，先不要修改工程。
```

### 2.5 修改已有工程

系统先检查当前工程并给出方案，然后停在确认。确认前画布不变。用户点「确认」才改图并重验；点「取消」则工程、版本和画布都不变。

```text
把当前 BPSK 工程改成 QPSK，其余条件不变。
```

### 2.6 观测

不需要修改确认。失败时停下来等用户。

```text
查看当前接收信号的频谱和星座图，给出主峰，只观察不要修改。
```

### 2.7 硬件配置

可以保存流图配置、做设备预检、展示风险，以及在显式授权后做有限时长发射。射频默认关闭。设备打开、发射运行和手机接收分别由 runtime 状态与空口 Evidence 证明。

```text
帮我配置 USRP B210。
```

缺少中心频率和采样率时应等待用户补齐。用户补齐后延续同一任务，再进入预检和确认。

## 3. 工作区

工作区三块：右侧对话、中间流图画布、状态栏（任务 / 运行时 / 规格）。

对话区展示用户与 DeepRadio 的交流，可内联产物图。画布展示当前 `.grc`。确认阶段保持当前画布，交付后原地刷新。session 内在画布 Ctrl+S 会增加工程版本，相关 Claim 待重验。

状态栏默认显示：

```text
任务名称 / 任务类型 / 当前阶段 / 序号
发射运行状态、run_id、剩余时长、末行日志
规格摘要（仿真为调制→信道→配方；BLE 为协议字段）
确认 / 取消（RF 计划与空口验收时换专用文案）
```

BLE 任务隐藏「改规格」。可展开「执行详情」查看各 Stage 的 attempt、Completion 计数和时间线。Claims 表默认折叠。底部状态栏显示阶段、档位、是否等待确认。

对话区控件：专业度（自适应 / 小白 / 学生 / 专家）、字体、重置、撤销到上一版本。可选勾选「一句话直出(baseline)」：该轮只根据一句话生成一份 `.grc`，不进入任务状态栏。

---

## 4. 确认、拒绝、取消、重置

- **确认 / 取消**：只对当前等待点生效。确认后才执行受限修改或硬件操作；取消则任务结束且工程不变。
- **改规格**：对尚未执行的仿真方案调整，留在当前任务里。BLE 规格只读展示。
- **画布保存**：工程已变，后续验证结论需要更新。
- **撤销到上一版本**：恢复快照，并同步当前任务版本。
- **重置**：紧急停止硬件进程，归档当前任务，开始新的会话状态。

未经确认不得执行：调制/配方切换、多块结构修改、硬件配置、真实设备发射、诊断后的大范围修复。

规格充分的纯仿真工程可以直接完成。

---

## 5. 专业度

小白、学生、专家是表达和解释档位。档位不改变技术验收标准，也不放宽「没确认就改图」或「没确认就发射」。

可量化指标：任务完成率、首次命中率、确认次数、阶段和工具调用数、失败恢复成功率、总时延、不同档位的轮次与完成质量。

## 6. BLE 与 SDR

```text
帮我用 PlutoSDR 发射一个 BLE 信号，local name 为 deepradio，
使手机上的 LightBlue 可以直接扫描到。
```

能力：

- 根据 local name 等参数生成 BLE 广播包、1M 波形和 Pluto/B210 发射流图，并做离线协议与结构校验。
- 只读发现和检查 PlutoSDR、B210，运行绑定探测得到的设备身份。
- 生成 B210 接收实时频谱流图；实时频谱出现在 GNU Radio 的 QT 窗口。
- 射频默认关闭。有限时长启动必须同时满足：离线校验和设备探测通过、用户确认射频计划、打开功能开关、合法实验环境。
- 受控运行显示 `run_id`、运行状态和最长时长；空口确认后自动停止。状态栏提示无需点击 GRC 运行箭头。
- 发射使用当前广告信道列表的第一项。指定 2.402 / 2.426 / 2.480 GHz 时分别对应信道 37 / 38 / 39；未指定频率时构建使用信道 37。三信道跳频调度未提供。
- PlutoSDR 支持显式授权后的有限时长 BLE 发射；空口是否通过由独立接收端（如 LightBlue）证明。B210 可生成 BLE 发射流图。实验记录见测试文档。

缺少对应运行记录和接收端 Evidence 时，禁止声称：

```text
设备已经打开
Flowgraph 已启动
RF 已发射
手机已收到本轮信号
LightBlue 已扫描到本轮目标名称
OTA 已经通过
```

空口成功由人工观察（LightBlue 截图）或独立接收设备证明。工作区在空口验收时可附加上传截图，与 `run_id`、目标名称一起进入 Evidence。

---

## 7. 交付范围

包含：单会话单任务、串行阶段、用户确认与取消、仿真构建/观测/诊断/修改、硬件配置与预检、离线 BLE 工件，以及显式授权下的 PlutoSDR BLE 有限时长发射。

不包含：多任务排队、并行阶段、跨工程任务、未确认的射频发射、广告三信道跳频调度。
